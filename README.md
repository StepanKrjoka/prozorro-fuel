# Пальне для силовиків у Prozorro

Збір і аналіз закупівель пального (бензин, дизель, скраплений газ, талони та паливні картки) силовими й оборонними
замовниками: Нацполіція, МВС, ДСНС, Нацгвардія, ДПСУ, Міноборони/ДОТ, військові частини, СБУ, УДО тощо.

Результат — сторінка з рейтингом постачальників (назва + ЄДРПОУ), переліком великих договорів і тендерів
з великою очікуваною вартістю, а також CSV-таблиці. Кожен рядок має посилання на тендер на prozorro.gov.ua,
а сирі відповіді API зберігаються в `data/raw/` — будь-яке число можна перевірити до першоджерела.

## Запуск (один раз налаштувати)

1. Створіть новий репозиторій на GitHub (наприклад, `prozorro-fuel`) і завантажте туди всі файли з цієї папки,
   зберігши структуру (зокрема `.github/workflows/update.yml`).
2. **Settings → Actions → General → Workflow permissions** → «Read and write permissions» → Save.
3. **Settings → Pages** → Source: «Deploy from a branch», Branch: `main`, папка `/docs` → Save.
4. **Actions → «Оновлення даних про закупівлі пального» → Run workflow**:
   - спершу виберіть `probe` — це діагностика за один місяць (2–3 хв). У лозі буде видно формат відповіді пошуку
     і кількість результатів на кожен CPV-код. Якщо якийсь код дає 0 — його варто перевірити;
   - потім `all` — повний збір. Перший запуск триває довго (орієнтовно 1–4 години: пошук обмежений ~60 запитів
     на хвилину). Наступні запуски інкрементні й ідуть щопонеділка автоматично.
5. Звіт з'явиться за адресою `https://<ваш-логін>.github.io/prozorro-fuel/`.

Локально: `python3 fuel.py probe`, `python3 fuel.py all` (Python 3.10+, без залежностей).

## Що де лежить

| Файл | Що містить |
|---|---|
| `config.json` | період, CPV-коди, ключові слова, пороги «великих» договорів, правила груп замовників |
| `overrides/buyers.csv` | ручне віднесення замовника до групи за ЄДРПОУ (`group` = id групи або `exclude`) |
| `data/contracts.csv` | усі договори на пальне: замовник, постачальник, ЄДРПОУ, суми, допугоди, строк дії |
| `data/suppliers_active_2026.csv` | рейтинг постачальників за договорами, що діють у 2026 році |
| `data/suppliers_signed_since_start.csv` | рейтинг за всіма договорами з початку періоду |
| `data/tenders.csv` | усі тендери вибірки з очікуваною вартістю і статусом |
| `data/items.csv` | позиції пального: опис, кількість, одиниця, ціна за одиницю (якщо вказана) |
| `data/buyers.csv` | замовники, їхня група і підстава віднесення — для перевірки класифікації |
| `data/search_log.json` | скільки результатів дав кожен пошуковий запит за кожен місяць |
| `data/raw/` | сирі JSON-відповіді API (тендери і договори), стиснуті gzip |

## Методологія

**Період.** Тендери, оголошені з 1 січня 2025 року (`date_from`). «Діючий у 2026» — договір, строк дії якого
закінчується 1 січня 2026 року або пізніше; якщо строк не вказано — підписаний у 2026 році. Так враховано
річні договори, укладені наприкінці 2025-го.

**Відбір.** Пошук prozorro.gov.ua за CPV-кодами (0913 — нафта і дистиляти, 09122 — пропан і бутан,
301631 — паливні картки) і текстовими запитами. Потім за повними даними перевіряється, що замовник належить
до однієї з груп і що в договорі є позиції пального (за CPV або ключовими словами).

**Сума.** Поточна вартість договору з модуля договорів (з урахуванням додаткових угод). Для розірваних
договорів — фактично сплачена сума (`amountPaid`), якщо її вказано. Суми — як оприлюднив замовник, переважно з ПДВ;
ознака ПДВ є в CSV.

**Обмеження.**
- Оборонні закупівлі за воєнного стану публікуються неповністю; у звітах оборонних замовників постачальник може
  бути не розкритий — такі договори видно окремим показником «постачальник не розкритий».
- Військові частини за назвою не розрізнити між ЗСУ, НГУ і ДПСУ.
- Пов'язані компанії автоматично не об'єднуються; це ручна перевірка (YouControl, Опендатабот).
- Якщо в договорі разом з пальним є інші товари (мастила, обслуговування), сума включає їх — такі договори
  позначено «є не лише пальне».
- Пошук prozorro.gov.ua віддає до 10 000 результатів на запит; скрипт автоматично ділить період, а випадки, де
  ліміт таки обрізав результати, записує в `data/search_log.json` (поле `truncated`).

Дані: Prozorro, відкриті дані з правом вільного повторного використання за умови посилання на джерело.
